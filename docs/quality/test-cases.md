> Detailed test cases derived from the [requirements](../product/requirements.md), [acceptance criteria](../product/acceptance-criteria.md), [business rules](../product/business-rules.md) and [API design](../architecture/api-design.md). The summary catalogue of all planned IDs is the [test plan](test-plan.md). Execution details are in the [execution report](test-execution-report.md). How tests are run is in the [testing strategy](testing-strategy.md).
>
> **Last executed:** 2026-10-18 (M5 invoices added; §2d M3, §2e M4, §2f M5). **Status values:** `Pass`, `Fail`, `Blocked` (the feature under test is not implemented), `Not Run` (manual or not yet executed). "Actual" records the observed result of the last run.

Conventions: **Level** U = unit, I = API integration (real MongoDB replica set), C = component (RTL), E = end-to-end (Playwright), A = architecture (lint). The automated test is named `file › test title`. The title starts with the ID shown here, so `grep` finds it. Common preconditions for I-level cases: a fresh `soloops_test_*` database with migrations applied, a fixed clock at 2026-10-16T09:00Z, and requests sent with `Origin: http://localhost:3000` and `X-Requested-With: soloops` unless stated otherwise.
